The model

The design chosen after two rounds of mock-ups (telecmd-mockups.html, telecmd-mockups-2.html); the spec and the plan are in telecmd.md. Each block shows what the device sent (device ▸) and what the page sent back (page ▸), keyed to numbered frames.

  • Writable telemetriesA device publishes a value and declares it writable. The page writes it with the line the device would send; the device's echo is the acknowledgement.
  • Actions are callsSeveral typed arguments, optional ones with defaults, a description for the action and each argument. The device answers run, then ok or err.
  • CMD off by defaultNothing is sent and no command UI is drawn: a wall screen needs no setting. Only controls views keep their controls, dimmed.
  • Light editors, no special viewsCMD on, any view edits in place, with editors that appear when used. A controls view (an option of the values view) is for driving.
  • Icons, not words sent · ✓ applied · ! not applied · ✕ refused / no answer. The why is in a tooltip.
  • The value is the reported oneNever the one typed. What was asked is a target (a caret, a dashed ghost) only until the device answers.

The CMD button

Two lines, green when on

  • Only shown when at least one device declared something writable.
  • CMD over a shaded OFF; on: tinted and outlined in green, ON in green.
  • Off at every page load (never remembered). Shortcut C.
  • The hover tooltip counts what can be commanded, per device.
  • Switching off releases joysticks at once. The island does not fade out while on.

Values view: editing in place

Any values view. CMD off: exactly as today. CMD on: a pen after the name of what can be written, and an editor that shows when it is used; the layout does not move. Same frames for every type: CMD off, CMD on, the edit, sent, applied, and how it fails.

A number with a range

The bar is the slider. A caret above it is the target: faint under the pointer, solid while dragged, bobbing while waiting, amber when the device kept something else. No caret = nothing asked. Clicking the number types a value instead.

A number without range, a text

The value is the field: underlined when CMD is on, a click edits it, Enter sends, Esc cancels.

A bool

A switch at the right of the written value. Clicked, it is striped on its new side until the echo.

Choices

Click the value: the choices open under it (up to 5 as buttons, a list beyond), and close once one is picked. The asked one is dashed until the echo.

Actions: calls with arguments

Declared like an RPC

One line for the action, one per argument, in order. An argument is declared with the keys of a writable telemetry (type, min, max, step, unit, choices), plus optional, default and desc.

  • The button says title (default: the name); desc is in its tooltip and at the top of the form.
  • No argument: one click sends (or confirm asks in place, or longpress holds 1 s). color colors it.
  • Arguments: the button opens the form. Required fields first; optional ones show their default as a placeholder and are not sent when left empty.
  • The page checks types and ranges before sending; the device checks again and may answer err.

A call from start to end

The row keeps one line. CMD off: the last result and how long it ran. CMD on: the same, and the button. The button carries the call: a spinner until run, then the running time; at the end, the icon and the duration.

How the device styles its buttons

No reserved names: a stop is an action like the others.

Controls view: driving

The option "controls" of the values view

  • Tiles with editors always drawn, bigger targets. The only kind of view that keeps its controls when CMD is off (dimmed: placed on purpose, the layout does not jump).
  • Made from the Edit panel (option "Controls"), or by the device: DASH|…|controls=1.
  • Continuous telemetries (rate / hold) are driven here: a pad for xy, a rocker for a number, a pad and a rotation rocker for a pose2d velocity (one stick when the device declares axes=x,yaw).
  • The knob is what the page sends, the green ring what the device reports. Released: back to rest, sent a few times, then nothing; the device stops on its own after hold ms.
  • Keyboard off by default; the view option turns on arrows or WASD (read by key position, only while the view has the focus, page shortcuts paused).

2D view: x / y / yaw

Move and turn a ghost

A writable pose2d (or xy) drawn in a 2D view. CMD on, hovering it shows a ghost with a move handle (center) and a turn handle (on a ring). Nothing goes out before Send (or Enter); Esc drops the ghost. Drawn in the frame of the telemetry.

Timeline

Requests and calls

  • A writable telemetry's lane: a tick above it per request (filled: applied, hollow red: refused, hollow amber: not applied). The band changes where the device reported the change.
  • An action's lane: a band per call, from run to its end, colored by the result, with its duration; a dotted line before run; a running call grows.
  • Hover: the call, its arguments, its times, the result or the error.

Log view

The conversation

What the page sent (in its own color, with the arguments of a call), between what the devices said; results as icons, a call with its duration.

Panels

Telemetries: the pen is a sign, not a handle

Writable telemetries and actions carry the pen (▶ for an action), CMD on or off. Dragging works as today: the default view of the telemetry, where it can be edited when CMD is on. No special drag: in-place editors are light enough not to need a kind of view. For driving, the Edit panel turns a values view into "Controls".

Sources: what each device accepts

A "Commands" section per device: writable telemetries and actions, the last result, the round trip (send → echo). The console shows what the page sent.
