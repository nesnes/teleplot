Second round for doc/telecmd.md (round 1: telecmd-mockups.html). Every block shows what the device sent (device ▸) and what the page sent back (page ▸), keyed to numbered frames: at rest, during and after an edit. Tags: proposed preferred, alternative, to test.

  • Changed since round 1The arm switch becomes the CMD button (command, as in telecmd), with no rate in it. No command palette, no chart overlay, no reserved action names.
  • Icons, not words sent · ✓ applied · ! not applied · ✕ refused / no answer. The why is in a tooltip.
  • CMD off = a wall screenOff hides what was added for commands. A dashboard shows no control unless it was made for that.
  • On hold3D view and image / camera views. The 2D view answers x / y / yaw.

The CMD button

In the top menu island, only when at least one device declared something writable. Two lines: CMD, and under it OFF (shaded) or ON. Shortcut C (free: Space, T, S, H, E, X are taken).

ATwo lines, tinted when on proposed

Off: the same grey as the other segments of the island, OFF in small shaded capitals. On: outlined and tinted in the command color, ON in that color. It stands out without shouting. The island does not fade out while CMD is on.

BFilled when on alternative

On: a solid red block. Unmistakable from across the room, but the loudest thing in the island for as long as commands are on.

CWith a count to test

A badge with the number of writable telemetries and actions: it tells a device came or went. Maybe only noise. A lamp variant puts a small light before ON / OFF.

What CMD off hides

"Additional" command UI: pen marks, the target on a bar, switches, choice buttons, action buttons. The open point is what a view made for commands shows when CMD is off. The same telemetries in every cell:

ADisplay views and command views proposed

A view is a command view when it was made for it: dragged by its pen from the Telemetries panel, the option in the Edit panel, or DASH|…|cmd=1 from the device. Every other view is a display view.

  • CMD off: display views are plain; command views keep their controls, dimmed (placed on purpose: the layout does not jump).
  • CMD on: command views work; display views only show the pen, and a click on it edits that row once, in place.
  • A wall screen built from display views shows nothing to click, CMD on or off.

BA row keeps its editor once used alternative

No kind of view. CMD on shows every editor everywhere. A row the user wrote from keeps its editor (dimmed when off); the others go back to plain. Nothing to configure, but a dashboard changes look with its history: a wall screen used once for tuning keeps its slider.

COff hides everything alternative

Like A, but command views hide their controls too when off (rows shrink to plain values, actions show their last result). The purest wall screen; a command dashboard jumps when CMD is switched.

A number with a range: the target on the bar

The bar already shows the value in its range (thresholds as ticks). The target must never hide the value, and must say clearly whether something is asked. Rule for the three designs: no target drawn = nothing asked. It shows faintly on hover, solid while dragging, dashed while waiting, and stays (amber) when the device did not take it. Clicking the number types a value instead.

AA hollow ring proposed

The value shows through the ring. Dashed while waiting for the device, glowing while dragged, amber when the device kept something else.

BA caret above the bar alternative

Nothing over the bar but a 1 px line: the bar stays exactly as in display. Small to grab, which matters little: the whole bar is the hit area.

CThe gap is striped alternative

What separates the value from the request is drawn: "how far from what I asked" reads at once. With a threshold tick in the gap it gets busy.

The other types, at rest, during and after

Same frames for each: CMD off, CMD on, the edit, sent, then how it ended. Shown in a command view (proposal A above).

1A number without range

No bar to drag: a click on the number turns it into a field (Enter sends, Esc cancels). The pen says it can be clicked.

2A bool

The value is written (on / off), the switch sits at the right. Clicked, the switch is striped on its new side until the echo.

3Choices

Up to 5 choices: buttons, the reported one filled, the asked one dashed. More: a select (frame 7).

4A text

Like a number without range: click the text to edit it.

Actions

An action has no value: it has calls, each with an execution. The device answers run when it starts, then ok or err: the page knows how long it ran from the device's own answers.

1How the device wants it shown

No reserved names: options sent with the declaration.

  • label: the text of the button (default: the name).
  • color: a palette or CSS color (red for a stop).
  • confirm: asks in place before sending.
  • longpress: held 1 s to send (the button fills). For something urgent that must not be hit by mistake.
  • action=xy (or another type): the argument, in a small form.

2A call from start to end

The button carries the call: a spinner until run, then the time it has been running; at the end, the icon and the duration under it. CMD off: the row keeps the last result (telemetry, not a control).

3Where the buttons go alternatives

Rows (above): one row per action, like a telemetry. Toolbar: the actions of the view as buttons at its bottom, their last results as icons. Progress: a percentage sent with run fills the button.

Joystick

1Pointer first, keys only on request

  • The knob is what the page sends; the green ring is what the device reports.
  • Released: it springs back, the page sends the rest value a few times and stops. The device stops by itself hold ms after the last write.
  • Keyboard off by default. WASD fits only some layouts (ZQSD on AZERTY) and clashes with the page shortcuts (S, E, T…). Turned on in the Edit panel, keys are read by position (event.code: where W is on QWERTY), only while the view has the focus, and page shortcuts pause meanwhile.

x / y / yaw on a 2D view

A new writable type pose2d: x:y:yaw (yaw in radians, like R of 2D| lines), in the frame of the telemetry. Two needs: say where to be (a goal, a pose), or drive (velocities).

AA goal: press where, drag towards proposed

Press at the place, drag to aim, release to send: one gesture, as in robotics tools. The reported goal stays drawn as the device says; the request is a dashed ghost until the echo.

BA pose: move and turn a ghost alternative

For "the robot is here" (relocalize) the telemetry is the robot itself. Hover it: a ghost with a move handle (center) and a turn handle (on a ring). Two gestures, more precise; nothing goes out before "Send" (or Enter).

CDriving: velocities teleoperation

Not a pose: vx:vy:wz, continuous (rate, hold). Holonomic: a pad for x / y and a rocker for the rotation, both spring back. Differential: one stick, up = forward, sideways = turn. The view lays out what the declaration has.

Timeline: calls and how long they ran

From the device's answers: a band from run to ok / err. Between the call and run, a thin dotted line (the call travelling, or queued on the device). A running call grows with the time. A writable telemetry's lane has a tick per request.

AA band per call on the action's lane proposed

Colored by result, the duration in the band when it fits; the reason of an error on hover.

BGrouped like a stack alternative

All the actions of a device under one lane "commands", a row per action. Compact when there are many actions rarely used.

Log view

1The conversation, icons only

What the page sent, between what the devices said. Outgoing lines in the command color; results as icons, a call with its duration.

Telemetries panel: display or command

Dragging a telemetry by its name makes a display view (as today); by its pen, a command view. The two must be told apart before the drop. Pens are always shown in the panel (it is where commands are found), CMD on or off.

AThe pen is a handle proposed

A small handle at the end of the row. Hovered, it is outlined and says what it does; its drag ghost says "command" in the command color, and so does the slot.

BThe drop slot asks alternative

Drag the row as today; over a "+" slot, a writable telemetry splits it in two: Display | Command. No new handle, but the choice comes late, while aiming.

Sources panel

1What each device accepts

A "Commands" section per device: writable telemetries and actions, the last result as an icon, the round trip (send → echo). The console shows what the page sent, in the command color.

On hold or dropped

  • Chart: droppedA chart is not a place for a command. Requests still show on timeline lanes and in logs.
  • 3D view: on holdDragging needs a plane and fights orbiting. 2D first.
  • Image / camera views: on holdPicking a pixel, or a point seen through the camera: after 2D.
  • Command palette: droppedCommands are given where they are displayed.
