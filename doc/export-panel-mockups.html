Export panel: saving and opening data

What the panel has to do

The Export button of the top menu (third panel of the left dock, shortcut X) is still "coming soon". The library can now write and read data files in two formats (doc/files.md): binary, the default, exact and small; text, the lines of the text protocol, which is also what a device can log to an SD card. Dashboards travel in both. These are the rules the ten mock-ups are judged against.

  • One obvious actionSaving everything in the default format is one click. Options exist, but nobody has to read them first.
  • Say what will happen before it happensHow many samples, which period, how big the file: shown before the click, not after.
  • Never lose data silentlyThe text format cannot hold everything: the count of what would be left out is shown next to the choice.
  • Opening a file is safeNothing is replaced unless asked. What the file brought is listed, and can be removed again.
  • Old data is still visibleA file from yesterday is longer than the 5 min data window: the panel says so and offers to keep it all.
  • Feedback for long workA large file shows its progress and can be cancelled.
  • Same words as the rest of the appData window, thinned, dashboards, telemetries: the vocabulary of the data menu and the panels.
  • Works by drag and dropA file dropped anywhere on the page is opened, as dashboard files already are.

Ten mock-ups

Each one is the whole left panel, at its real width. They mostly differ in how much they ask before saving and in how they treat an opened file.

1Two cards: Save, Open

The plainest version. One primary button saves everything in the default format; the line above it says what "everything" is. Options hide behind a link and unfold in the card (format, period, telemetries, dashboards).

Good
Nothing to learn, one click for the common case, the summary is always visible.
Less good
Options are one click away, so the text format and partial exports are easy to miss. An opened file leaves no trace in the panel.
Best for
Newcomers, and as the resting state of any of the richer versions below.

2A sentence with choices

The options are words of one sentence that reads as what will happen. Each underlined word is a menu: everything / what is on screen / chosen telemetries; the whole session / what is zoomed / the last minute; with or without dashboards; binary / text.

Good
Every option is visible without a form, and the result is self-explaining. Very compact.
Less good
Menus inside a sentence are less discoverable than plain controls, harder to translate, and the sentence wraps awkwardly in a narrow panel.
Best for
Occasional users who want to check what they are about to save.

3Three questions, always visible suggested for saving

What, when, format: three segmented controls with the defaults already selected, so saving is still one click. The recap next to the button follows the choices live. "On screen" is what the displayed dashboard shows; "Zoomed" is only enabled while a time group is zoomed; "Choose…" opens a telemetry checklist.

Good
Options are discoverable without being in the way; defaults are visible, so the user knows what one click does. Segmented controls match the top menu.
Less good
Takes more height than version 1. Three options per row is the limit at this width.
Best for
The general case: it serves the newcomer and the expert with the same screen.

5The timeline first

The data menu's timeline (how much of the window is filled, where data was thinned) becomes the main control: drag its handles to choose the period. It starts on what is zoomed on the dashboard, so "save this incident" is: zoom on it, open the panel, save.

Good
Ties export to the zoom, the gesture users already know. Shows that the oldest part was thinned before it ends up in a file.
Less good
Handles are small in a narrow panel; choosing telemetries is pushed to the split button's menu. With several time groups, "zoomed" needs a rule (the group last used).
Best for
Debugging sessions: keeping the thirty seconds around an event.

6A checklist with sizes

The telemetries, grouped by label as in the Telemetries panel, each with what it weighs. Unticking the camera divides the file by three, and the user sees it before saving.

Good
Full control, and the sizes teach what is heavy (the same idea as "heaviest telemetries" in the data menu).
Less good
A long list for a simple task; it duplicates the Telemetries panel. The one-click save drowns under the list.
Best for
Sharing a small extract of a heavy session. Good as the "Choose…" screen of version 3 rather than as the panel itself.

7Three tabs: Save, Open, Recent

Saving and opening are different moments, so each gets a tab and room for its own options; "Recent" lists the files saved and opened in this session. The panel is named "Files" rather than "Export".

Good
Room for import options (add or replace, serial log) and for the SD card explanation without crowding the save screen.
Less good
Tabs hide two thirds of the panel; a small feature gets a heavy structure. Import options shown before a file is chosen are abstract.
Best for
If import grows more options later (time offset, renaming, column mapping).

8Opened files as cards suggested for what was opened

Like the Sources panel has a card per connection, each opened file stays as a card: its period, what it brought, what went wrong, and actions. "Show its period" zooms the dashboard on the file's time range (a file from yesterday is otherwise far to the left of live data). "Remove its data" undoes the import. Saving is one split button; its menu holds format and scope.

Good
Opening becomes reversible and traceable. It answers the two questions that follow every import: "where is it?" and "how do I get rid of it?".
Less good
Needs the library to remember which samples came from which file (telemetries have a source today, samples do not): removal would work per telemetry, or per time range. Save options are hidden in a menu.
Best for
Comparing recordings, and devices that log to SD cards: several files in one session.

9Two buttons and an undo

The smallest panel that works: defaults for everything, no option on screen, and forgiveness instead of confirmation. After opening, a message offers Undo for a few seconds. It could even live in the data menu instead of a panel.

Good
Fastest for both actions. Undo is better than a question asked beforehand.
Less good
A modifier key is not discoverable; partial exports are impossible; a timed Undo is easy to miss, and the user never sees what the file contained.
Best for
A first release, or as the top of version 8.

10A receipt before opening suggested for opening

Once a file is chosen, it is read without being stored and the panel shows what it holds and what opening it will do: which telemetries are new, which get more samples, how dashboards are renamed, and that the data window must grow. Then one button. The same receipt, after opening, becomes the card of version 8.

Good
No surprise: every side effect is announced, including the one users would not guess (the data window). The "clear first" option appears when it means something.
Less good
One more click for every import; reading a large file twice (once to describe it) takes time, unless the first pass keeps its result.
Best for
Files that come from elsewhere (a colleague, an SD card), where the content is not known in advance.

Suggestion

Combine three of them: the save card of 3 (three questions with defaults, so one click still saves everything), the receipt of 10 when a file is chosen or dropped, which then stays as a file card of 8. The checklist of 6 would be the screen behind "Choose…". Open points to settle: the extension of the binary file (.teleplot here), whether "Remove its data" is worth tracking samples per file, and whether the panel keeps the name "Export" or becomes "Files".
