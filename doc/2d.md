# 2D drawings and frames

Teleplot draws flat things too: a map with a robot and its path, a zone, an arrow, a label, a box around what a detector found in a picture. Three ideas hold it together.

1. **2D is 3D with z = 0.** A `2D|` line is a `3D|` line written flat; it gives the same telemetry. Nothing is sent twice, and both the 2D and the 3D view show everything.
2. **A frame** makes the positions of a telemetry relative to another one, which carries it along.
3. **A pixel frame** draws a telemetry in the pixels of a picture, without any camera model.

Everything is in the library (`packages/teleplot-js`): the text parser (`040`), the scene model (`113`, shared with the 3D view), the 2D view (`115-viewScene2D.js`), the image view (`114`). The binary protocol carries the same things (`binaryProtocol.md`).

## The `2D|` lines

```
2D|robot,field:S:rect:P:1.2:0.8:R:1.57:W:0.3:H:0.2:C:blue
2D|ball,field:S:circle:P:2:1:RA:0.11:C:orange:O:0.8
2D|route,field:S:line:PT:0:0:1:0.5:2:2:3:2:C:green
2D|lane,field:S:line:PT:0:0:1:0.5:2:2:3:2:LW:0.35:C:gray
2D|zone,field:S:polygon:PT:0:0:1:0:1:1:0:1:C:red:O:0.3
2D|speed,field:S:arrow:P:1.2:0.8:V:0.5:0.2
2D|goal,field:S:text:P:3:1:TX:"Goal A"
2D|map,field:S:rect:P:1.5:1:W:3:H:2:T:url:"field.png"
2D|robot:P:1.3:0.8:R:1.6
```

Same grammar as `3D|` (`name,label:timestamp:properties|flags`, see the README and `3d.md`): send everything once, then only what changes.

| Property | In a `2D|` line | In a `3D|` line |
|---|---|---|
| `P` position | `x:y` (z is left as it is: 0 unless a 3D line said otherwise) | `x:y:z` |
| `R` rotation | one angle, around z, in radians | `roll:pitch:yaw` |
| `W`, `H` | extent along x, along y | `W` x, `D` y, `H` z |
| `RA` radius | of a circle | of a sphere, a cylinder |
| `S` shape | `rect` (the default), `circle`, `line`, `polygon`, `arrow`, `text`; also the solids | the same, `cube` by default |
| `PT` points | `x:y:x:y...` as many as needed (line, polygon), in the frame of the shape | `x:y:z:x:y:z...` |
| `V` vector | `x:y` of an arrow, from its position | `x:y:z` |
| `TX` text | the text, in quotes when it holds `:` `;` or `|` | same |
| `LW` line width | in the units of the frame (see below) | same |
| `TS` text size | height of a text, in the units of the frame | same |
| `C`, `O`, `T` | color, opacity (0 to 1), texture | same |
| `F`, `FPX` | frame, pixel frame (see below) | same |

Other lines that a 2D view displays, unchanged: `pos:1.2:0.8|xy` (a position; its trail is the path: an XY plot, as in Teleplot V1), `scan:1:0:0;0.7:0.7:0|pc` (a point cloud; a flat scan has z = 0), and every `3D|` shape.

**Widths and sizes are in the units of the frame**, like every other value.

- A line **with** `LW` has that width: it grows when the view zooms in, and is a band on the ground of a 3D view. It is never drawn thinner than one pixel, so it cannot vanish when zooming out.
- A line **without** `LW` is as thin as the screen draws, at any zoom: no width was stated, nothing is misrepresented.
- Same for texts: with `TS` a text has that height in the scene; without, a steady readable size on the screen.

## Pictures in a scene

```
2D|plan:S:rect:P:1.5:1:W:3:H:2:T:url:"field.png"
2D|plan:S:rect:P:1.5:1:W:3:H:2:T:telem:camera

PNG|map:iVBORw0KGgo...
2D|map:P:2:1.5:W:4:H:3:R:0.1
```

Two ways, in 2D and in 3D views alike:

- **A rectangle with a texture** (a floor plan, a field): a picture given by its url, or the pictures of an image telemetry (`T:telem:name`).
- **An image telemetry that is given a place itself**: a `2D|` (or `3D|`) line addressed to the name of the image telemetry, with its position, size and rotation. It then shows its own pictures there, each one at the time it was sent: a map that a robot builds and sends as pictures, a thermal image laid on a plan. Its position is its center; `W` and `H` are the extent of the picture in your units (the picture is stretched to them: give them the proportions of the picture).

The picture is laid on its rectangle as it is; it is never modified. An image telemetry that has **camera intrinsics** (`K`) stays a camera: it is drawn as what it sees, and its pictures are shown by image views. An image telemetry without any place is not part of a scene (drop it in an image view).

## Frames

```
2D|heading:S:arrow:V:0.4:0:F:robot
2D|wheel:S:rect:P:0:0.14:W:0.12:H:0.04:F:robot
2D|scan:F:robot
```

`F:name` puts a telemetry **in the frame of another one**: its positions (and its orientation, its vector, its points) are relative to the pose of that telemetry. When the frame moves or turns, what is in it follows, without being sent again.

- Anything can be in a frame: shapes, cameras, point clouds (the pose of their sensor), points (`xy`, `xyz`).
- Anything that has a place can be a frame: a shape, a camera, the sensor of a cloud, a point (a point has a position but no orientation).
- A frame can be in a frame (up to 16 deep). A name that is unknown, or frames that go in circles, leave the telemetry in the scene.
- The frame is found by name, whichever protocol sent it.
- **Time**: a telemetry is placed with the pose its frame had at the time shown. Each position of a trail, and each cloud of an accumulation, is placed with the frame as it was at the time of that sample: the trail of a point carried by a robot is where the point really went.
- `F:` alone puts the telemetry back in the scene.

The scene itself is the default frame: **x forward, y left, z up**, in your units.

## Pixel frames

```
2D|det1:S:rect:P:120:80:W:40:H:60:C:red:FPX:camera
2D|det1.name:S:text:P:100:42:TX:"person 0.92":C:red:FPX:camera
```

`FPX:name` puts a telemetry in **the pixels of the pictures of an image telemetry**: u to the right, v down, (0, 0) at the center of the top left pixel. What a detector finds in a picture can be shown on it as it is, with no knowledge of the camera.

- Only the image views of that picture draw it. It has no place in a 2D or 3D scene, so those views leave it out: a box at pixel 120 is never drawn 120 units away on a map.
- An image view takes the telemetries drawn in its pixels by itself (`pixelDrawings` option), once each: one that is removed from the view stays removed.
- The position of a `rect` is its center. A positive angle turns from u towards v. `LW` and `TS` are in pixels of the picture.
- This is another way than the camera model: scene telemetries are still drawn over a picture through the intrinsics and the pose of its camera (`3d.md`). Both can be used on the same picture.

## The 2D view

`TELEPLOT.view.ViewScene2D` (view type `2d` in dashboards and in the editor): the scene seen from above, without perspective.

- Drag to move, wheel to zoom on what is under the pointer, double click to frame everything again. Until it is moved it keeps everything drawn so far in the frame (it only ever zooms out), with the origin unless the content is tiny and far from it.
- Same scale on both axes. A grid every 1, 2 or 5 × 10ⁿ units with its values along the edges; axes from the origin (x red, y green).
- Options: grid, axes, legend, decimals, trail length, the point cloud options of the 3D view, and **how the scene is looked at**: `axisRight` and `axisUp` name the axis of the scene that points to the right of the view and the one that points up, each `x`, `y`, `z`, or `-x`, `-y`, `-z` for their opposite.

  | `axisRight` | `axisUp` | |
  |---|---|---|
  | `x` | `y` | from above (the default) |
  | `-y` | `x` | from above, x to the top: what is in front of a robot is at the top, its left to the left |
  | `y` | `x` | north up, east to the right (frames where x is north and y east): the scene seen from below |
  | `x` | `z` | from the side |
  | `y` | `z` | from behind (x goes away from the viewer) |

  Any pair of different axes works. The grid shows the values of those axes (reversed when the axis is), the axes drawn are the ones that lie in the plane (x red, y green, z blue), and what is nearer to the viewer is drawn over the rest (what is higher, from above).
- Flat shapes, positions and flat scans are drawn as they are. **3D telemetries are drawn as what they cover on the ground**: a cube is its footprint (turned as the cube is), a sphere or a cylinder a circle, an STL file the outline of its vertices, a cloud its points, a point its trail, a camera the triangle of what it sees. Only the drawing drops z; the data is untouched and nothing is computed from it but this projection.
- What is higher is drawn over what is lower; backgrounds on the ground go under the grid.
- Like the other views it follows the cursor and the zoom of its time group, and its legend is the one of the 3D view (click to hide, hover to highlight).

In the other direction, **the 3D view shows flat telemetries lying on the ground**: rects and circles as plates, lines, polygons and arrows where they are, texts facing the viewer, a textured rect as a floor plan under the solids.

## Which view by default

Both views show both kinds; this only decides what a telemetry gets when nobody arranged it (automatic dashboard, a label that is a path):

- a 2D view for `xy` positions, flat shapes, and point clouds whose points all have z = 0;
- a 3D view for solids, `xyz` points and other clouds;
- the image views of a picture for what is drawn in its pixels.

With a view label, telemetries of the label that are displayed the same way share a view, and a 2D or 3D view of a label also takes what the other kind has in that label.

## Library

| | |
|---|---|
| `TELEPLOT.view.ViewScene2D` | the view; `ViewScene2D.buildItems(sources, options)` computes what is drawn as a list of items, without any canvas (unit tested), `draw` and `drawGrid` put them on a canvas |
| `ViewScene3D.shapeState(telem, time)` | everything about a shape at a time, placed in the scene (its frame applied): also `vector`, `text`, `lineWidth`, `points`, `framed` |
| `ViewScene3D.frameOf(telem, time)` / `poseOf` / `pointPositions` | the pose of the frame of a telemetry, of a telemetry as a frame, the positions of a point in the scene |
| `ViewScene3D.pixelFrame(telem)` / `isFlat(telem)` | the image telemetry whose pixels it is drawn in; whether a 2D view is its default |
| `TELEPLOT.datastore.findByName(name)` | a telemetry by its name, whichever protocol it came from |

Tests: `tests/viewScene2D.test.js`. Demos: "2D drawings and frames" in `test.html`. The robot sample of the webapp uses all of it: what the robot carries is in the frame of its body, a map shows the scene from above, and a box is drawn around the obstacle in the pixels of its camera.
