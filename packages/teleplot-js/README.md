# teleplot-js

The library of Teleplot: everything about telemetry and how it is displayed. It ingests data (text and binary protocols, from a
Teleplot server, a serial port or the page itself), stores it, and draws views (charts, values, logs, timelines, 2D, 3D, images,
joysticks) arranged in dashboards. The web application ([packages/webapp](../webapp/README.md)) is built on it, and any page can use it.
Documentation of what it does: [doc/](../../doc/README.md).

## Use it in a page

`teleplot-js.js` is one file, with no dependency (Vue, uPlot and three.js are inside). Releases ship it alone.

```html
<div id="plot" style="height: 300px"></div>
<script src="teleplot-js.js"></script>
<script>
  initTeleplot();                                                          // creates the global Teleplot
  Teleplot.connection.addConnectionTeleplotServer("127.0.0.1", 8080);      // a Teleplot server (packages/server)
  const row = new Teleplot.view.ViewLayout("plot", "default");             // an element id, a time group
  Teleplot.view.addView(row);
  row.addView(Teleplot.view.createView("chart", ["sin"], "default"));     // a chart of the telemetry "sin"
</script>
```

`test.html` shows every feature, each in a card with the code that built it: it is the reference of the API.

## Build

```bash
./build.sh
```

It concatenates `src/NNN-*.js` in the order of their number into `teleplot-js.js`, and copies it to [`packages/webapp/libs/`](../webapp/libs/).
Everything lives inside one function, `initTeleplot(TELEPLOT)`, opened in `000-init.js` and closed in `999-export.js`.

| Files | What |
| --- | --- |
| `001` to `004` | embedded libraries: uPlot, Vue, three.js (`004` is generated by [`tools/embed-three.js`](tools/embed-three.js)) |
| `01x` | state, protocol constants, datastore (telemetries), clients |
| `02x` | connections: Teleplot server, serial port, local connection, commands ([telecmd.md](../../doc/telecmd.md), [sources.md](../../doc/sources.md)) |
| `03x` | older data inputs (UDP, serial through a V1 server) |
| `040`, `041` | parsers: text ([textProtocol.md](../../doc/textProtocol.md)) and binary ([binaryProtocol.md](../../doc/binaryProtocol.md)) |
| `10x` | views, layouts, stacks, theme, colors, decimator ([performance.md](../../doc/performance.md)), runs of texts, pictures ([depth.md](../../doc/depth.md)), fingers on the views ([touch.md](../../doc/touch.md)) |
| `110` to `118` | values, chart, log, 3D, image ([3d.md](../../doc/3d.md)), 2D ([2d.md](../../doc/2d.md)), timeline ([time-views.md](../../doc/time-views.md)), joystick, graph ([graph.md](../../doc/graph.md)) |
| `150`, `151` | dashboards, dashboards as text ([dashboard-text.md](../../doc/dashboard-text.md)) |
| `160` | data files ([files.md](../../doc/files.md)) |
| `998` | the update loop (30 per second) |

## Pages

- `test.html`: a demo of every feature (serve the folder, or open the file).
- `test-performance.html`: a stress test (text or binary, set through the URL: `?series=4&rate=1000&charts=1&protocol=binary`),
  which reports the frame rate, the ingestion, the memory and the update time. See [performance.md](../../doc/performance.md).
