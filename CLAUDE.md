# Teleplot V2 — project memory

Rework of Teleplot for better performance and UI.

## Guidelines
- Teleplot displays telemetry, it never invents any: no interpolation between samples (use the last sample at or before the time shown), and incoming data is never modified (ex: images are not undistorted; adapt what is drawn instead). Removing old samples to bound memory is allowed (data window, memory limit); creating or averaging samples is not.
- Minimize dependencies; always tell the user when wanting to add one.
- Goals: performance of data ingestion and display; UI intuitive for newcomers yet powerful for experts; retro-compatible with the V1 text-based protocol.
- For each new feature, decide whether it belongs in the lib (`packages/teleplot-js`) or in the GUI (`packages/webapp`).
- `packages/teleplot-js/`: everything about telemetry and how it is displayed. Split into `src/` files aggregated by `build.sh` (libs included). Keep `test.html` updated with a demo of ALL lib features: it is a page of sections (side index) made of cards; add a feature with `demo(title, what to look for, [width, height], (id) => {...})` in its section (the card shows the view and the code of that function), and the code that sends its telemetries with `data(title, note, () => {...})`.
- `packages/webapp/`: GUI for end users, exposes all lib features.
- `clients/`: source libraries per language, as simple as possible.
- `doc/`: documentation, must be expanded and kept updated.
- `README.md`: V1 info + V2 targets at the end; must be rewritten and kept updated.
- Legacy V1 (reference only, do NOT update): `server/`, `vscode/`, `images/`, other old folders.
- Note: the folder is `packages/` (plural), not `package/`.

## Build
- `cd packages/teleplot-js && ./build.sh` concatenates `src/NNN-*.js` by numeric prefix into `teleplot-js.js`, then copies it to `packages/webapp/libs/`. Always rebuild after editing `src/`.
- Everything lives inside one function `initTeleplot(TELEPLOT)` opened in `000-init.js` and closed in `999-export.js`. Vue (003), uPlot (001/002) and three.js (004, `TELEPLOT.THREE`, generated by `tools/embed-three.js`: do not edit by hand) are embedded.

## Protocol
- Binary: little-endian everywhere (C++ `BinaryEncoder` default, JS `_parseDataBinary_LITTLE_ENDIAN`), marker 0x10, version 1, client id uint16, typed sections (client name, telem attr, data number/2D/3D/text/image, 3D shape position/rotation/quaternion/color/opacity/size/texture, camera intrinsics/distortion), checksum still TODO. Spec in `doc/binaryProtocol.md`; constants in `src/011-protocol.js`.
- View label: `name,label` in text, `TELEM_ATTR_VIEW_LABEL` in binary. Telemetries with the same label share a view (per kind of view, titled with the label) in the auto dashboard; the webapp's Telemetries panel has a card per label to drag them together. It only decides the first placement. Views can follow labels (`options.followLabels`, `view.followLabel(label)`): new telemetries of a followed label that the view can display (`suitsTelemetry`) are added to it; the auto dashboard's label views and the views a label card is dropped on (drag type `text/x-teleplot-drag-label`) follow it. A label also ties a camera to its scene: a 3D view takes the image telemetries of its label (its cameras), and in the auto dashboard the image view of a labelled image telemetry follows the label too (shapes, points and clouds of the label are drawn over the picture), whichever comes first.
- Point clouds (lidar scans...): data type `TELEM_DATA_POINT_CLOUD` (35), one sample = one whole cloud, stored as typed arrays in 3 channels (positions `Float32Array` x,y,z..., intensities `Float32Array` or null, colors `Uint8Array` r,g,b... or null). Cartesian, in the sensor frame (2D scan: z = 0); the sensor pose is sent as shape position / rotation on the same telemetry. Text: `name:x:y:z;x:y:z|pc` (a field alone = timestamp; 4, 6 or 7 values per point add intensity and / or rgb). Binary: multi-part like images. Drawn by `ViewScene3D` (kind "cloud", `__updateCloud`, options `pointSize`, `pointColorByHeight`, `cloudCount` / `cloudInterval` for accumulation) and so by `ViewImage` overlays. See `doc/3d.md` "Point clouds".
- Text: V1 `name:value` style, UDP port 47269; commands UDP 47268. `DASH|` lines describe dashboards (see "Dashboards as text"). Flags `xy`, `xyz` (3D point), `pc` (point cloud), `t` (text as a state), `log` (text as a log: attribute `TELEM_ATTR_LOG` 7, also set by `>` lines), `np`, `clr`. State or log is the same text data and both views display both; it only changes `suggestViewType` ("values" or "log"), so the default view, and in the auto dashboard logs without a label share one log view. `3D|name:props` lines describe shapes (and, with `K`/`DC`, the camera of an image telemetry): each property is stored in the data type (or attribute) the binary protocol has for it, so both protocols give the same telemetry.

## Server and webapp
- `packages/server/main.js` (Express + express-ws): relays UDP 47269 to WebSocket on 8080 (text batched every 50 ms, binary forwarded as is), forwards commands to UDP 47268, serves `../webapp`.
- Webapp: Vue 3 (`main.js`, `index.html`, `components/` panel-help/sources/telemetries/edit + dashboard.js + dashboard-editor.js, `css/style.css` + `css/editor.css`, icofont). Default connection 127.0.0.1:8080.

## Performance
- Charts decimate data before giving it to uPlot (avoids `uPlot.join` on all stored points): see `doc/performance.md`. Stored data is not reduced by the display; it is only reduced when the memory limit is reached (`TP.state.memoryLimit` / `memoryPolicy`, default "thin": `telemetry.thinOldest()` keeps real samples, fewer of them, and charts mark the thinned part), see `doc/performance.md` "Memory". Chart option `decimation` (default true).
- `packages/teleplot-js/test-performance.html` = stress/perf page (text or binary protocol, configurable through URL, reports fps/ingestion/heap/update time). Keep it working when touching ingestion or views. `test.html` links to it.
- Files are CRLF (Windows checkout): keep CRLF when editing/creating files.

## Time groups
- Views of a group (`view.group`, state in `TELEPLOT.view.groups[name]`) share zoom and cursor. `view.group` is no longer set once: every view and layout has options `timeGroup` ("inherit" default / "dashboard" / "custom") and `timeGroupName`, and `TELEPLOT.view.resolveTimeGroups(root, base)` (100-views.js) gives each view of a tree its group (custom key = base + `TIME_GROUP_SEPARATOR` + name). Dashboards do it on every update (`TELEPLOT.dashboards.resolveTimeGroups`, hook in 998) with base = the dashboard name, so moving a view, renaming a dashboard or changing the option just works; groups nobody uses any more are pruned.
- `TELEPLOT.dashboards.setTimeGroup(dashboard, view, mode, name)` ("custom" without a name creates "Time N"), `getTimeGroups`, `renameTimeGroup`. Marks (tag + frame, `Views.__syncTimeGroup`, `view.timeGroupMark`) show where a group starts: always with `TELEPLOT.view.showTimeGroups` (the webapp sets it in edit mode), otherwise only while zoomed. GUI: "Time group" in `panel-edit.js`. See `doc/dashboard-editing.md` "Time groups".

## Dashboards as text
- `151-dashboardText.js`, spec in `doc/dashboard-text.md`: one line per view addressed by its path, `DASH|Robot/top/Motion:chart:speed,accel|w=3` (type: row/column/grid/stack/chart/values/log/3d/image/none; options = layout and view option names, plus `w`, `h`, `title`, `time`, `follow`; `%XX` escaping). The same lines are the export file, a message of the text protocol (040) and the binary section `SECTION_TYPE_DASHBOARD` (2). No JSON form: one grammar.
- `exportText(name)`, `importText(text)` (always new dashboards, "Robot 2" when taken), `receiveLine/receiveText` (applied only when the line differs from the last one received for its path: user edits survive repeats; `TELEPLOT.dashboards.received`, raw), `onReceivedDashboardHooks` (the webapp shows the dashboard unless the user is on one of their own or editing). Views keep the key of their path in `view.key`.
- A view label that is a path (`speed,Robot/Motion:12.5`) places its telemetry (`placeTelemetry`, new telemetry hook): dashboard and view created, one view per kind (`Motion`, `Motion#values`), skipped by the auto dashboard.
- Views accept names of telemetries that do not exist yet; a hook in 103 swaps the name for the id when a binary telemetry with that name shows up.
- In the webapp the library is wrapped in Vue proxies: dashboards (like views) are compared by id, never `===`, and always taken from `TELEPLOT.dashboards.dashboards` (a bug of this kind passed the lib tests and only showed in the browser).
- GUI: a per-dashboard export button in the dashboard list of `top-menu.js` (`exportDashboardFile`); its "Import…" hands the file to the Export and import panel (`ctx.droppedFiles` + `ctx.exportOpen`), the only place where files are opened; Help step "Your own dashboard".

## Data files
- File extensions written by the webapp: `.teleplot` (binary), `.teleplot.txt` (text protocol lines, dashboards alone included), `.teleplot.csv`. Opening does not depend on them (content is sniffed; `.csv` only forces CSV).
- `160-files.js`, spec in `doc/files.md`: `TELEPLOT.files.exportBinary/exportText(options)` return `{parts, samples, skipped}` (parts for a Blob; options `telemetries`, `from`, `to`, `dashboards`), `importData(data, options)` / `createImport()` (`add(piece)` cut anywhere, `finish()`), `isBinary`. A file is what a device would have sent: text = lines of the text protocol (a device can log them to an SD card), binary = `FILE_MAGIC` then `{length uint32}{packet}`; importing goes through `parseDataText` / `parseDataBinary` (pause lifted meanwhile, `DASH` lines redirected to `dashboards.createImport` by `dashboards.withImport`, what was added counted by `datastore.watchAdds`).
- Binary is lossless (tests compare the whole store after a round trip): values a float32 would round go in `SECTION_TYPE_TELEM_DATA_FLOAT64` (36, generic for numeric data types), timestamps are written so that the parser reads the same double back, name-identified telemetries use the reserved client id `CLIENT_ID_NAMED` (0xFFFF). Text is what the text protocol can say: what it cannot is skipped and counted, never altered.
- Known behaviours: importing adds samples (a file imported twice is stored twice); the data window counts from the newest sample of each telemetry, so a long old file needs `extendWindow` (or a longer window).
- CSV (`exportCSV`, `previewCSV`, and opened by `createImport`): numbers, 2D/3D numbers and text only; layout columns (empty cell = no sample at that very time, never filled) or lines; separator `,` `;` tab; numbers always with a point; time iso / ms / s. `estimate(format, options)` sizes an export before writing it.
- `createImport({dryRun: true})` describes a file without storing anything (`datastore.dryRun` + `rememberIdentity`, undone after each piece because live data keeps arriving between pieces). `removeImported(result)` takes an import back by time range per telemetry (samples are not tagged with their origin).
- GUI: `webapp/components/panel-export.js` (right dock like Help and in its place, `ctx.exportOpen`, shortcut X; design studies `doc/export-panel-mockups.html` and `-2.html`, mock-up A): an Export section (what / when / format, checklist behind "Choose…", CSV settings with a preview table, recap before saving) and an Import section (receipt from a dry run, options per format, Open / Cancel), visually distinct, then the files of the session (show its period, remove its data, save again). Files dropped on the page (and picked from the dashboard list) go to it through `ctx.droppedFiles`. When a file holds data and dashboards, the receipt has a checkbox for each (import options `data: false` / `dashboards: false`). `File` objects must be `markRaw` (a proxied File cannot be read). Helpers tested in `webapp/tests/export.test.js`.

## Dashboard editing
- Edit mode is a GUI feature (see `doc/dashboard-editing.md`, target design `doc/dashboard-edit-prototype.html`): `webapp/components/dashboard-editor.js` (commands + pills/DnD chrome, `initDashboardEditor(TP)`), `components/panel-edit.js` (right panel following the selection), `css/editor.css`. "+" slots (add a view from a menu, or by dropping a telemetry; shown outside edit mode only during a telemetry drag) live in dashboard-editor.js. The lib only has generic helpers: `TELEPLOT.view.suggestViewType/createView`, `view.clone()/dispose()`, `TELEPLOT.view.removeView/disposeView`, `addTelemetry/removeTelemetry`, `title` option, `getOptionsSchema()`, container `layout.height`, `renameDashboard`.
- Children of a layout come out of a reactive array as Vue proxies: compare views by id, never by `===`.
- A view that gets a new DOM element (moved, stack tab switched) is disposed and mounts again on its next update (`Views.__before_update`).

## Webapp notes

- Fields bound to application state use the `v-value` directive (`main.js`) with `@change`, never `:value`: panels redraw several times per second (timers, live data) and `:value` writes the stored value back over what is being typed. This bug came back three times (data menu, Edit panel names, view options) before the directive existed. When adding a text or number input, type in it in a browser while data flows before calling it done.

- Never let a UI framework proxy sample storage: `Telemetry.data` is `markRaw` (see doc/performance.md). Regression test in `tests/datastore.test.js`. Same for the caches built from it: `ViewChart.decimators` is `markRaw` (a proxied decimator compares its raw source with a proxy, never matches, and rescans all the data on every update: found on 2026-10-10 by a long session in the webapp, the lib test pages are not reactive and do not show it). When measuring performance, measure in the webapp too.
- `TP.dashboards.enableAutoDashboard(name, onCreated)` (lib, `150-dashboards.js`) charts new telemetries automatically (number -> chart, others -> current value, `autoplot=false` skipped); the webapp enables it as "Live" and activates it on creation.
- Data menu (popup of the pause / rate control, in `top-menu.js`): data window (default 300 s) with a timeline of how much of it is filled (`TP.datastore.getTimeSpan()`: the telemetry that goes the furthest back), memory ring and stacked bar, policy at the limit, heaviest telemetries, clearing. The lib does the work (`TP.state.dataTimeout`, `memoryLimit`, `memoryPolicy`, `TP.datastore.getMemoryUsage/getTimeSpan/checkMemory/clearData/forgetTelemetries`).
- Top menu: `webapp/components/top-menu.js` (floating island: dashboard switcher, pause/resume + rate, left panels as one segmented control with counts, Edit, Help as a word at the right end; shortcuts Space/T/S/H/E (shown in tooltips), fades out when the mouse rests), see `doc/top-menu.md`. Layout: docks that slide their width (left: Telemetries or Sources, `ctx.sidePanel`; right: Help, `ctx.helpOpen`, then the edit panel), welcome screen, help panel: see `doc/webapp-layout.md`. Help panel (`panel-help.js`): a ladder of message formats (`HELP_STEPS`, each tested against the parser in `tests/help.test.js`), written for the way the user sends data (`HELP_SENDERS`: terminal, Python, C++, Arduino), with the parts of a message colored (`helpColorize`) and a field to try a message from the page (`helpDescribe` says what was understood). Pause is the lib's `TP.state.isPaused` (data is ignored while paused). `components/telemetry-rate.js` estimates rates (also used by the Telemetries panel). In `index.html` custom elements that have siblings after them must be closed explicitly (`<top-menu></top-menu>`): `<x/>` is not self-closing in in-DOM templates.
- The old tree panel (`panel-dashboard.js`) was replaced by the edit mode. DOM behaviour (pills, drag and drop) has no automated test: check it in a browser (serve `packages/webapp`, `app._container._vnode.component.proxy` gives the root component, `.editor` the editor; click the sample start button of the Help panel, then Edit).
- Sources panel: `webapp/components/panel-sources.js` (summary, a card per source, serial console, add a source, data controls), see `doc/sources.md`. Serial is Web Serial only (Chromium); to test without a device, give `TP.connection.addConnectionSerial` a fake port (an object with `open`, `close`, `getInfo`, and `readable` / `writable` streams, as in `tests/connectionSerial.test.js`). Telemetries know their source (`telemetry.sourceId`).
- Sample data: `packages/webapp/components/sample-robot.js` (self-contained robot simulation: numbers, 2D, text, 3D shapes and a 3D path, and a ray-traced camera with lens distortion that publishes its intrinsics, distortion and pose) builds its own "Robot sample" dashboard (top row: 3D scene, the two camera views in a column, values over the logs; bottom row: charts and a stack; the plain camera view is alone in a custom time group "Live", so it stays on the latest picture); its telemetries have autoplot=false so the auto dashboard ignores them. The help panel only has the start/stop button.
